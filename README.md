# 티스토리 블로그 스킨 메이커

클로드 코드로 티스토리 블로그 스킨을 만든 저장소입니다.
지금은 **손으로 만든 스킨 한 벌**과 **그 지식을 옮겨 담은 스킨 생성기**가 함께 들어 있습니다.

## 저장소에 들어 있는 것 세 가지

| 폴더 | 무엇인가 |
|------|---------|
| `src/` | 손으로 만든 티스토리 스킨 **Code Editor Blog**. 0.9.8 부터 1.10.0 까지 버전별로 통째로 보관 |
| `webapp/` | 스킨 생성기. 사용자가 자기 API 키를 넣고 대화로 자기 스킨을 만들어 가져가는 정적 페이지 |
| `design-handoff/` | 생성기 화면의 시각 디자인 의뢰서와 결과물 |

`reference/` 에는 실제 티스토리 스킨 두 벌(Odyssey, BookClub)이 들어 있습니다. 치환자 사용법이
막힐 때 문서보다 이쪽이 빠릅니다.

## src - 손으로 만든 스킨

`TISTRORY_skin_guide.md` 가 원본 문서인데 토큰이 너무 커서, 자주 쓰는 것만 뽑은
`TISTORY_quick_reference.md` 를 따로 만들어 두고 그것을 보며 만들었습니다.

**버전 폴더를 통째로 남기는 이유**는 롤백 기점 확보입니다. 스킨은 실제 블로그에 올려 봐야
문제가 드러나는 일이 많아서, 되돌릴 지점이 없으면 고칠 때마다 위험합니다.

가장 최근 버전은 `src/1.10.0/` 입니다. 설치는 스킨 편집 화면에 `skin.html` 과 `style.css` 를
붙여넣고, `images/` 아래 파일은 **파일업로드 탭에서 따로** 올려야 합니다. 이걸 빠뜨리면 404 가
나면서 레이아웃이 통째로 깨집니다.

### 만들며 알게 된 것

문서에 없는 치환자를 지어내도 티스토리는 **오류를 내지 않고 조용히 아무것도 출력하지 않습니다.**
그래서 업로드해도 틀린 줄 모릅니다. 실제로 `[##_tag_##]`, `<s_article_rep_tag>`,
`<s_not_index_article_rep>` 셋을 그렇게 쓰고 있었고, 라이브 페이지에서 발견한 뒤 공식 문서
24개 페이지를 전수 대조해서야 나머지가 드러났습니다. 이 경험이 아래 생성기의 검사기로 들어갔습니다.

## webapp - 스킨 생성기

서버가 없습니다. 로그인도, 수익화도 없습니다. 키는 브라우저를 벗어나 사용자가 고른
LLM 제공자로만 갑니다. 만든 스킨은 파일로 내려받습니다.

```
E1 키 등록 - P1 컨셉 4안 - P2 세부 정하기 - W1 대화로 작업 - D1 내려받기
```

핵심은 화면이 아니라 **`webapp/harness/`** 입니다. `src/` 를 만들며 얻은 치환자 계약서와
함정 목록을 코드로 옮긴 것으로, 모델이 낸 결과를 실제 파일까지 만들어 보고 검사한 뒤에만
반영합니다.

실행하려면 로컬 서버가 필요합니다(ES 모듈과 fetch 가 `file://` 에서 막힙니다).

```
python -m http.server 8000
```

열고 나서 `/webapp/` 로 들어갑니다. 테스트는 `node webapp/test/*.test.mjs` 입니다.

## 문서

- `CLAUDE.md` - 에이전트가 읽는 작업 규칙. 버전 관리 규칙과 함정이 여기 있습니다
- `TISTORY_quick_reference.md` - 자주 쓰는 치환자 (먼저 볼 것)
- `TISTRORY_skin_guide.md` - 전체 문서 (막힐 때 볼 것)
- `docs/screens/` - 생성기 화면 기획. 화면에 관한 한 이것이 정답입니다
- `docs/archive/` - 폐기된 계획. 왜 그 길로 안 갔는지가 남아 있습니다
