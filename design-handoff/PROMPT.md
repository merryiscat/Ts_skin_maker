# 티스토리 스킨 생성기 - 화면 디자인 의뢰

## 서비스 소개

정적 웹페이지 하나로 된 도구다. 사용자가 자기 LLM API 키(Anthropic/OpenAI/Google)를
등록하고, 대화로 티스토리 블로그 스킨을 만들어 ZIP 으로 내려받는다.
서버 없음, 로그인 없음, 수익화 없음. 키는 브라우저를 벗어나지 않는다.

화면 흐름: E1(키 등록) - P1(컨셉 4안 고르기) - P2(세부 정하기) - W1(대화 작업) - D1(내려받기).
W1 에서 S1(설정 패널)을 열고 닫는다.

## 의뢰 내용

6개 화면(E1, P1, P2, W1, D1, S1)의 시각 디자인.
기능과 정보 구조는 확정돼 있고(와이어프레임이 정답), 시각적 완성도만 끌어올리는 작업이다.

현행 화면의 문제:
- 요소 간 위계가 약하다. 제목/본문/보조 텍스트가 크기만 다르고 무게가 없다
- 여백과 정렬에 리듬이 없어 폼이 나열로만 보인다
- 결과물 도식(레이아웃 미니어처 4종)이 조악하다
- 전체적으로 "믿고 키를 맡길 만한 도구" 인상이 부족하다

## 결과물 형식 (중요)

- 화면별 정적 HTML 파일 6개 + 공용 CSS 1개(design.css)
- design.css 상단에 디자인 토큰을 CSS 변수로 정의할 것:
  색상 팔레트, 타이포 스케일, 간격 스케일, radius, 그림자
- HTML 은 현행 마크업(current/e1-dom-snapshot.html)의 클래스명과 구조를
  유지할수록 좋다. 실제 앱은 JS 가 이 DOM 을 생성하므로, 구조가 같으면
  CSS 만 갈아끼워 포팅할 수 있다. 구조를 바꿔야 한다면 바꾼 이유를 주석으로 남길 것
- JS 동작 재현은 불필요. 상태가 여러 개인 화면은 대표 상태를 그리고,
  중요한 변형(E1 키 확인 전/후, W1 생성 중/실패)은 같은 파일 안에 나란히 배치
- 반응형: 360px 모바일에서 성립하고 768px, 1024px 에서 확장

## 지켜야 할 규칙

- 이모지 금지. 카피, 코드, 주석 전부
- CSS 프레임워크 금지(Tailwind, Bootstrap 등). 손으로 쓴 CSS 만
- 외부 웹폰트 지양. 시스템 폰트 스택 우선 (정적 페이지라 외부 의존을 줄인다)
- 카피는 wireframes/ 의 확정 카피를 그대로 쓸 것. 서술형 친절체 금지, 짧고 건조하게
- 용어 통일 (wireframes/README.md 의 표):
  프리셋(템플릿 X), 시작점(베이스 X), 미리보기(프리뷰 X),
  내려받기(다운로드 X), 검증(밸리데이션 X), 지시(프롬프트 X)
- 노출 금지: API 키 원문(등록 후 뒤 4자리만 표시), 시스템 프롬프트 본문,
  모델 응답 원본 JSON

## 디자인 방향 제안

개발자 도구다운 담백함과 신뢰감. 밝은 바탕 흑백 기조에 절제된 강조색 1개.
이 도구가 만들어 주는 스킨 자체가 코드 에디터 스타일이라, 도구도 그 정체성과
어울리는 절제된 인상이면 좋다. 더 나은 방향이 있다면 대비되는 2안까지 제시해도 된다.

## 동봉 파일 안내

  - wireframe.css, index.html(전체 목록)
  - README.md : 도메인 규칙, 용어 표, 노출 금지 항목

  > **의뢰가 끝난 뒤 이 폴더는 지웠다.** `docs/screens/` 의 사본이었고(해시까지 동일),
  > 같은 것이 두 벌 있으면 다음에 기획을 고칠 때 어느 쪽이 정답인지 알 수 없게 된다.
  > 원본은 `docs/screens/` 에 있고 그것이 정답이다. 위 목록은 의뢰 당시 무엇을 보냈는지의
  > 기록으로 남겨 둔다.

  - screenshot-e1.png : 현행 E1 화면 모습
  - e1-dom-snapshot.html : 실제 렌더된 E1 의 DOM (클래스명 참고용, 이 구조를 유지할수록 포팅이 쉽다)
  - shell.css : 현행 공용 CSS (토큰 변수명 참고)
  - index.html : 앱 셸 (상단 앱바 + 단계 표시)
