의도

처음 하는 사람이 막히는 원인은 설명 부족이 아니라 위치를 못 찾는 것이다. 그래서 티스토리 관리자 화면을 도식으로 그려 지금 누를 곳에 굵은 테두리를 준다.

왼쪽 할 일 목록에 다섯 단계를 항상 띄워 둔다. 실험 A 만 쓰면 지금 어디쯤인지 감이 없으므로 보편 B 의 순서 감각을 이 목록으로 흡수했다. 다만 다음 단계를 잠그지는 않는다. 두 번째 설치부터 답답해지기 때문이다.

4단계 파일 올리기를 가장 무겁게 다룬다. 이 프로젝트에서 실제로 빠뜨려 화면이 통째로 깨진 적이 있고, 원인을 찾는 데 시간이 걸렸다. 그래서 빠뜨렸을 때 어떻게 보이는지를 5단계에서 그림으로 대조시킨다. 증상을 미리 알아야 나중에 스스로 원인을 찾는다.

같은 이름 파일은 덮어쓰기가 안 되는 경우가 있어 삭제 후 추가를 명시한다.

ZIP 은 보관용이라고 분명히 적는다. 받아 두고 그것만 올리면 된다고 오해하면 설치가 되지 않는다.

남의 화면을 그리는 위험을 줄이는 방법

이 안의 유일한 구조적 약점은 티스토리가 관리자 화면을 바꾸면 도식이 거짓말이 된다는 것이다. 세 가지로 막았다.

  • 도식을 단순하게 그린다. 버튼 모양이나 색이 아니라 위치 관계와 탭 이름만 남긴다. 세부를 그릴수록 빨리 틀린다.
  • 메뉴 경로를 항상 병기한다. 그림이 틀려도 경로 문자열로 찾아갈 수 있다.
  • 기준 날짜를 표시한다. 사용자가 화면이 다르다는 것을 알아챌 수 있고, 상태 5 에서 대처법을 준다.

대안

  • 보편 A 전체를 한 화면에 - 재설치에는 가장 빠르지만 처음 하는 사람이 파일업로드 탭에서 막힌다. 그 지점이 이 화면의 핵심 난관이라 탈락.
  • 보편 B 체크리스트로 순서 강제 - 빠뜨림은 막지만 위치를 알려주지 못한다. 순서 감각만 왼쪽 목록으로 가져왔다.
  • 실험 B 지금 할 것만 크게 - 헷갈릴 여지가 없지만 티스토리 화면을 오가다 어디였는지 잃기 쉽다. 오히려 이 화면에서는 전체 목록이 보이는 편이 낫다.

미정

  • 티스토리 관리자 화면이 바뀌었을 때 누가 알아채고 고칠지. README 유지 항목에 넣었지만 갱신 신호가 사용자 제보뿐이다.
  • "빠뜨렸을 때" 그림을 몇 종류나 줄지. 지금은 파일 올리기 누락 하나만 그렸다. CSS 를 안 붙여넣은 경우도 흔할 수 있다.
  • 단계 완료 표시를 새로고침 후에도 유지할지. 티스토리 관리자를 다른 탭에서 오가므로 유지되는 편이 맞아 보인다.
  • 스킨을 새로 등록하는 경로와 기존 스킨을 고치는 경로가 다르다. 지금은 후자만 그렸다.
