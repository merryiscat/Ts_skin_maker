### [진행 2026-08-30] W1 캡처 + 표시(그리기) + 이미지 전달 (비전)

미리보기를 이미지로 굳혀 손으로 표시하고 그 이미지를 모델에 비전으로 함께 보내는 기능(피드백).
코드 끝, 실호출 눈 확인 남음. 스크린샷·비전 둘 다 새로 넣었다.

- **비전 입력을 providers 에 추가.** 중립 메시지 `{role,content,image?}` 에 image(data URL) 를 얹으면
  어댑터가 제공자별로 변환: Anthropic `{type:'image',source:{base64}}`, OpenAI `{type:'image_url'}`,
  Google `{inlineData}`. 헬퍼(parseDataUrl/anthropicContent/openaiContent/googleParts) export 하고
  providers.test 로 세 형식 검증. 추천 모델은 다 비전 됨(텍스트 전용 모델 고르면 API 가 거부).
- **캡처는 라이브러리 없이 SVG foreignObject.** 미리보기가 same-origin 이라 문서를 XMLSerializer 로
  통째 SVG 안에 넣어 Image→canvas 로 그린다(`captureIframe`, w1.js). 보이는 부분만 잘라 PNG.
  한계: 외부 폰트/CSS(구글폰트 등)는 이미지로 뜰 때 안 불러와져 폴백된다(레이아웃·색·표시는 잡힘).
  data: 이미지라 canvas 오염 없음. 실패 시 toast.
- **표시(그리기) 모달**: 캡처 이미지를 canvas 에 깔고 빨간 펜으로 자유 드로잉(마우스/터치). "이 이미지로"
  누르면 합쳐 `pendingImage`(data URL)로. 발판에 "이미지 첨부됨/첨부 지우기" 칩. 보낼 때 그 이미지를
  마지막 user 메시지에 실어 보내고 비운다(1회용). 지시 없이 이미지만이면 "표시한 부분을 고쳐 주세요".
- edit-prompt 시스템에 "이미지가 오면 사용자가 표시한 부분을 참고해 고쳐라" 한 줄 추가.
- 미확인: 실호출 눈 확인 — 특히 foreignObject 캡처가 이 미리보기에서 실제로 잡히는지(브라우저 의존),
  비전 지시가 표시한 부분만 바꾸는지. 캡처가 부실하면 html2canvas(CDN) 대안 검토.

## 알고 있는 한계

이건 버그가 아니라 "이렇게 만들기로 한 것"이다. 고치려 들기 전에 이유를 볼 것.

- **`chatModels` 필터는 이름 기반이다.** `webapp/providers.js` 의 `NOT_CHAT` 정규식으로
  음성·이미지·임베딩 모델을 걸러 낸다. 새 종류가 나오면 못 걸린다.
  **빼는 목록**으로 만든 것은 의도다 — 모르는 이름은 남긴다. 반대로 만들면
  새로 나온 대화 모델이 사라져 쓸 수 없게 되고, 그쪽이 더 나쁘다
- **단가 표는 조회 시점 기준이다.** 앤트로픽은 claude-api 카탈로그(2026-06-24),
  OpenAI/Google 은 공식 요금 페이지(2026-08-15) 조회분. 가격이 바뀌면 표도 낡는다.
  E1 비용 표는 어림값이라고 화면에 적어 두었다
- **미리보기가 못 잡는 것이 있다.** 렌더러는 티스토리가 본문에 씌우는 래퍼를
  재현하지 않는다. 문단 여백 같은 문제는 실제 블로그에 올려야 드러난다.
  `webapp/harness/pitfalls.js` 가 그 목록이다
- **브라우저가 ES 모듈을 캐시해서 코드를 고쳐도 옛것이 뜬다(테스트 함정).** 같은 포트로
  다시 열면 `webapp/screens/*.js` 등 동적 import 모듈이 디스크 캐시로 서빙되어 수정이
  반영 안 된다(2026-08-25 Playwright 검증 중 실제로 겪음 — 8002 는 옛 4안 UI, 포트를
  8003 으로 올리니 새 코드가 떴다). 변경을 브라우저로 확인할 땐 **포트를 올리거나**
  캐시 무시 새로고침을 할 것.
