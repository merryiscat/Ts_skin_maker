#### [진행 2026-08-25] P1 실호출 확인 (OpenAI gpt-5.6-luna, Playwright)

`.env` 의 OpenAI 키로 P1 을 실제로 돌려 눈으로 확인했다. 기술 블로그 / 여행 두

- **4안 생성 잘 된다.** 넷의 (layout, listStyle) 조합이 매번 서로 다르고, 용도별로
  방향이 뚜렷이 갈린다(기술=문서형/촘촘, 여행=사진격자/대표사진). 가장 싼 luna 로도 품질 양호.
- **"다시 만들기" 가 note 를 반영한다.** "미니멀·텍스트 위주" 를 넣으니 사진격자/대표사진이
  빠지고 plain/제목중심이 들어왔다. reqSeq 경합 처리도 눈에 띄는 문제 없음.
- **추천 모델 필터가 실제로 작동.** `recommendedFor` 가 받아온 목록에 있는 것만 카드로
  띄운다(e1.js:488). gpt-5.6-* 5종이 다 떴으니 이 키의 실제 목록에 실존함을 확인.

아직 눈으로 못 본 것: **P2 · W1 · D1 · S1 팝업.** (P1 만 확인함)

**여기서 새로 잡은 안건 4개:**

1. **P1 에서 "쓴 토큰" 카운터가 사라진다.** 셸 캔버스 머리의 "모델 · 쓴 토큰 N" 줄을
   P1 의 `drawCards` 가 "4안 + 용도" 배지로 덮어쓴다(p1.js:124). 정작 실측하려는 그
   숫자를 생성 화면에서 못 본다. → 캔버스 머리에 토큰/비용을 같이 남기거나, 배지를 머리
   말고 다른 자리에 둘 것.
2. **`estimateCost` 가 캐시 할인을 무시한다.** 3회 다 입력 2140 중 2101 이 cached 인데
   (프롬프트 캐싱 작동), `estimateCost`(providers.js:627)는 전체 입력에 정가를 매긴다.
   luna 에선 미미하지만 Sol/5.5 처럼 입력이 비싼 모델에선 어림값이 실제보다 크게 나온다.
   → usage.prompt_tokens_details.cached_tokens 를 반영할지 검토.
3. **desc↔wire 불일치가 나올 수 있다.** 여행 4안 "여행 아카이브" 는 desc 에 "대표
   이미지를 촘촘하게" 라 적었는데 wire=dense 라 스케치엔 사진 없이 제목만 나온다.
   시스템 프롬프트가 "desc 와 wire 는 어긋나면 안 된다" 고 했는데도 모델이 어겼다.
   → dense 를 고를 때 desc 에 이미지 얘기를 넣지 말라고 프롬프트를 조일 것.
   (정정: 처음엔 "wireToSketch 가 dense 에 showThumbnail=true 를 주는데 wireframe 렌더가
   무시한다" 고 적었으나, 탐색 결과 wireframe.js:53 이 dense 에도 작은 썸네일을 그려 서로
   일관됨 — 라벨 없는 16px 라 "제목만" 처럼 보였을 뿐. 이 안건 자체는 아래 5번 처리로
   대부분 사라졌다: 이제 팔레트가 아니라 모델이 wireHtml 을 직접 지어 desc 와 함께 낸다.)
4. **용도를 흐름 안에서 못 바꾼다.** 용도는 E1 에서 한 번만 묻는다. P1 에서 용도를
   바꾸려면 페이지를 새로 열어 E1 부터 다시 타는 수밖에 없다(키도 탭 전용이라 같이 날아감).
   → P1 에 "용도 바꾸기" 경로를 둘지 검토.

5. **[근본] 4안의 다양성이 부분적으로 착시다 — 같은 archetype 이 이름만 바꿔 반복된다.**
   스케치 단계는 layout 3종 × listStyle 5종 = 고정 15칸 조합에서만 고른다
   (concept-prompt.js `WIRE_LAYOUTS`/`WIRE_LISTS`). 그래서 용도가 바뀌어도 같은 조합이
   재등장한다. 실측 예:
   - 개발 1차 3안 "코드 아카이브"(sidebar-right+dense) == 개발 2차 2안 "우측 인덱스형"
     (sidebar-right+dense) — wire 가 완전히 동일. 이름만 다른 같은 화면.
   - 여행 4안 "여행 아카이브"(no-sidebar+dense) 도 같은 dense 골격에 도메인 명사만 교체.
   코드 주석은 "고정 5종 돌려쓰기가 아니다(최종 구조는 CSS 로 열림)" 라고 하지만, 정작
   사용자가 보고 고르는 스케치 단계는 팔레트 재조합이라 넷이 "달라 보이게" 만드는 힘이 약하다.
   → 검토안: (a) 한 세트 안에서 (layout,listStyle) 중복 금지는 이미 있으나, listStyle 만
   같아도 사실상 비슷해 보이니 "넷의 listStyle 도 최대한 겹치지 말라" 를 프롬프트/스키마에
   추가. (b) 팔레트를 늘리거나(예: 목록 밀도/썸네일 위치 축을 분리), 스케치를 팔레트 선택이
   아니라 자유 생성으로 되돌리는 것(단 2026-08-23 에 자유 컨셉→스키마 이관 실패로 선택형으로
   바꾼 이력 있음 — e1.js:345 주석. 되돌리려면 그 실패부터 풀 것). (c) name/desc 가 도메인
   명사만 바꾼 재탕이 되지 않게 "넷의 성격이 뚜렷이 달라야" 를 강화.

#### [개편 2026-08-26 옵션2] 순서 뒤집기 — 용도 → 레이아웃 4안(A~D) → 무드 → 실현

피드백 3건: (1) 전반 컨셉 6필드가 과함 → **한 줄 + 채팅 다듬기**, (2) 일반/혁신이 실제로 안
다르고 "혁신"이 허울 → **A/B/C/D 로, 4안을 구조적으로 확실히 다르게**, (3) 값 판단(일반/혁신)
제거. 그리고 사용자 제안으로 **순서를 뒤집음**: 컨셉을 먼저 정하지 않고 "용도에 맞는 레이아웃"
을 먼저 고르고 무드는 그 다음. 근거: 흑백 와이어는 색·무드가 아니라 구조를 보여주는 것이므로
구조를 먼저 고르는 게 각 단계가 보여주는 것과 일치하고, 무드 제약이 없어 4안 다양성이 저절로
풀린다(컨셉 × 레이아웃 두 축은 그대로).

- **새 순서**: E1 용도 → **P1 레이아웃 4안(A~D, 용도 기반, 무드 없음)** → **C1 무드(한 줄 + 채팅)**
  → P2 실현 → W1 → D1. `SCREENS = E1,P1,C1,P2,W1,D1`.
- `concept-prompt.js`: `OVERALL_CONCEPT_SCHEMA` 를 `{name, summary}` 한 줄로 축소. `VARIANT_ROLES`
  (2일반2혁신) → `VARIANTS`(A~D + 서로 다른 seed: 사이드바목록/사진격자/히어로/비대칭매거진).
  `buildVariantPrompt({seed, ...})` 는 컨셉이 없으면 "무드는 다음 단계" 로 안내, 있으면 앵커로.
- `p1.js`: 용도+시드로 4와이어 순차 생성(avoid 로 겹침 방지), 라벨 A~D, 역할 뱃지 제거, 확정→C1.
- `c1.js`: P1 뒤로. 한 줄 무드 제안 + 채팅 누적 다듬기(directions), 캔버스에 무드 + 고른 레이아웃
  와이어 함께 표시, 확정→applySelectedConcept(look=무드, hint=고른 레이아웃)+P2.
- `state.js`: `setOverallConcept` 가 더는 genConcepts 를 지우지 않음(4안이 먼저 뽑히므로).
- `conversation.js`: STEPS `purpose→layout→concept→detail→chat`, 고른 레이아웃/무드 로그 말풍선.

## 알고 있는 한계

이건 버그가 아니라 "이렇게 만들기로 한 것"이다. 고치려 들기 전에 이유를 볼 것.

- **`chatModels` 필터는 이름 기반이다.** `webapp/providers.js` 의 `NOT_CHAT` 정규식으로
  음성·이미지·임베딩 모델을 걸러 낸다. 새 종류가 나오면 못 걸린다.
  **빼는 목록**으로 만든 것은 의도다 — 모르는 이름은 남긴다. 반대로 만들면
  새로 나온 대화 모델이 사라져 쓸 수 없게 되고, 그쪽이 더 나쁘다
- **단가 표는 조회 시점 기준이다.** 앤트로픽은 claude-api 카탈로그(2026-06-24),
  OpenAI/Google 은 공식 요금 페이지(2026-08-15) 조회분. 가격이 바뀌면 표도 낡는다.
  E1 비용 표는 어림값이라고 화면에 적어 두었다
- **미리보기가 못 잡는 것이 있다.** 렌더러는 티스토리가 본문에 씌우는 래퍼를
  재현하지 않는다. 문단 여백 같은 문제는 실제 블로그에 올려야 드러난다.
  `webapp/harness/pitfalls.js` 가 그 목록이다
- **브라우저가 ES 모듈을 캐시해서 코드를 고쳐도 옛것이 뜬다(테스트 함정).** 같은 포트로
  다시 열면 `webapp/screens/*.js` 등 동적 import 모듈이 디스크 캐시로 서빙되어 수정이
  반영 안 된다(2026-08-25 Playwright 검증 중 실제로 겪음 — 8002 는 옛 4안 UI, 포트를
  8003 으로 올리니 새 코드가 떴다). 변경을 브라우저로 확인할 땐 **포트를 올리거나**
  캐시 무시 새로고침을 할 것.
