의도

키를 요구하기 전에 무엇을 받는지 먼저 보여준다. 도식 넷을 올려 "답하면 이런 게 나온다"를 한눈에 준다. 실험 A의 만져 보기와 목적은 같되, 예시 대화와 예시 스킨을 따로 유지하는 비용은 지지 않는다. 도식은 P1과 같은 방식으로 그려 두 화면이 같은 언어를 쓰게 한다.

키 확인은 모델 목록 조회로 한다. 세 제공자 모두 모델 목록 엔드포인트가 있고 토큰이 들지 않는다. 한 번의 무료 호출로 키가 살아 있는지 확인하고 쓸 수 있는 모델까지 같이 받아온다. 확인이 무료라는 사실을 입력칸 아래에 적어 사용자가 누르기를 망설이지 않게 한다.

확인 전에는 모델을 고를 수 없고 시작 버튼도 눌리지 않는다. 잘못된 키로 P1까지 갔다가 되돌아오는 낭비를 없앤다.

모델은 추천 몇 개와 받아온 전체 목록을 나눈다. 추천은 코드에 박아 두고 설명과 비용을 붙인다. 전체 목록은 확인할 때 받아온 것이라 항상 최신이다. 목록에 없는 것도 직접 입력할 수 있다. 추천 밖 모델은 단가를 모르므로 비용을 표시하지 않고 그 사실을 밝힌다.

제공자를 바꾸면 확인 상태가 풀린다. 키도 모델도 제공자에 매여 있으므로 이전 확인 결과를 물려받으면 안 된다.

오류를 세 가지로 나눈다. 형식 오류는 호출 전에 걸러 비용을 아끼고, 거부와 네트워크 실패는 문구를 달리해 멀쩡한 키를 의심하며 시간 버리는 일을 막는다. Google 은 잘못된 키에 401 이 아니라 400 으로 답하므로 상태 코드만으로 판정하면 안 된다.

대안

  • 보편 B 단계 분리 - 제공자별 안내는 정확하지만 아무것도 못 본 채 세 번 넘겨야 한다. 안내 정확성은 상태 4의 연동 전환으로 흡수했다.
  • 실험 A 만져 보고 나중에 키 - 이탈 방지는 가장 강하지만 예시 스킨과 예시 대화를 골격 변경 때마다 갱신해야 한다. 도식으로 대체했다.
  • 실험 B 키를 마지막에 - 요구 시점은 자연스럽지만 답을 다 적고 키가 없는 걸 알면 헛수고가 된다.
  • 키 확인을 생략하고 P1의 첫 호출로 대신하기 - 호출 한 번을 아끼지만 그 호출은 유료다. 무료 확인이 가능하다는 것을 확인한 뒤 폐기했다.

미정

  • 받아온 목록에는 오래된 모델과 용도가 다른 모델이 섞여 있다. 이름 규칙으로 걸러 보일지 전부 보일지.
  • 추천 목록과 단가는 코드에 박혀 있어 낡는다. 갱신 주기와 담당을 정해야 한다. README 에 유지 항목으로 적어 두었다.
  • 키 저장을 켰을 때 어디에 둘지. localStorage 는 확장 프로그램이 읽을 수 있다.
  • 도식 넷을 고정으로 둘지 방문할 때마다 다르게 보일지.
