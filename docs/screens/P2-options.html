실험 B

이 화면을 만들지 않는다

컨셉이 이미 세부를 다 정했다. 그대로 작업 화면으로 보내고, 바꾸고 싶으면 거기서 말하거나 세부 패널을 열게 한다. 화면 하나를 줄이는 대신 W1 이 조금 무거워진다.

강점
진입이 가장 짧다. 컨셉을 고르면 곧바로 결과를 본다. 세부에 관심 없는 사람에게 결정을 강요하지 않는다.
약점
무엇을 바꿀 수 있는지 모른 채 대화만 하게 된다. "사이드바 위치를 바꿀 수 있다"는 사실 자체를 알려주는 자리가 없어지고, 그 결과 매번 API 를 태워 가며 물어보게 된다.

네 안이 갈리는 지점

  • 보편 A - 전부 펼쳐 놓고 관심 있는 것만 건드리게 한다.
  • 보편 B - 묶음으로 쪼개 매번 가볍게 결정하게 한다.
  • 실험 A - 항목 목록을 없애고 도식 위에서 지목하게 한다.
  • 실험 B - 이 화면의 존재 자체를 묻는다. 컨셉이 다 정했으면 넘어가면 된다.

어느 안이든 들어가야 하는 것

  • 모든 항목에 컨셉이 정한 기본값이 채워져 있을 것. 빈칸에서 시작하면 컨셉을 고른 의미가 없다
  • 아무것도 안 건드려도 진행될 것
  • 바꾼 것이 도식에 즉시 반영될 것. 반영이 안 보이면 무엇을 고른 건지 알 수 없다
  • P1 의 "섞고 싶은 것"이 미리 반영돼 있을 것
  • 컨셉 다시 고르기로 P1 에 돌아가는 길. 세부를 만지다 컨셉이 틀렸다고 느낄 수 있다
  • 여기서는 API 를 쓰지 않는다. 전부 플래그 조작이라 비용이 들지 않는다는 점이 W1 과 다르다

미정

  • 혼합 가능. 보편 A 로 전부 펼치되 도식의 영역을 누르면 해당 항목으로 스크롤되는 식.
  • 항목을 아홉 개 다 보일지, 컨셉이 건드린 것만 앞에 두고 나머지는 접을지.
  • 여기서 정한 값을 W1 에서 다시 바꿀 수 있는지. 대화로도 되고 세부 패널로도 되면 두 경로가 생긴다.
