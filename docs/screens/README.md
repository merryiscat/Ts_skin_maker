# 화면 기획

티스토리 스킨 생성기 웹페이지의 화면 설계. 흑백 HTML 와이어프레임으로 작성한다.

## 영역 prefix

| Prefix | 영역 | 범위 |
|--------|------|------|
| E | 진입 | 서비스 소개, API 제공자 선택, 키 등록, 모델 선택 |
| P | 프리셋 | 시작점 선택 |
| W | 작업 | 대화, 미리보기, 검증 상태, 코드 열람 |
| D | 산출 | 내려받기, 티스토리 설치 안내 |
| S | 설정 | 키 교체, 모델 변경, 대화 초기화 |

채번은 prefix + 순번. ID는 고유하게 유지하고 다른 화면에서 참조할 때 ID로만 부른다.

## 화면 목록

| ID | 이름 | 상태 |
|----|------|------|
| E1 | 진입 / 키 등록 | **확정** (보편 A + 결과물 도식) |
| P1 | 컨셉 고르기 | **확정** (보편 B + 컨셉 질문 + 컨셉 4안 생성) |
| P2 | 세부 정하기 | **확정** (보편 A 로 훑고 실험 A 로 다듬는 두 상태) |
| W1 | 작업 화면 | **확정** (보편 A) |
| D1 | 내려받기 / 설치 안내 | **확정** (실험 A, 관리자 화면 도식) |
| S1 | 설정 | **확정** (보편 A, 겹치는 패널) |

흐름은 `E1 - P1 - P2 - W1 (반복) - D1`. W1에서 S1을 열고 닫는다.

**컨셉을 먼저 정하고 그다음 세부로 내려간다.** 사이드바 위치나 목록 형태를 컨셉보다 먼저 물으면 사용자가 답할 수 없다. P1의 4안은 레이아웃이 아니라 "이 블로그가 방문자에게 무엇을 하게 할 것인가"로 갈린다.

`P1-options.html`은 "시작점을 어떻게 고르게 할까"를 다룬 4안이라 확정된 P1과 층위가 다르다. 폐기하지 않고 남겨 두되 이 차이를 알고 볼 것.

전체 목록은 `index.html`에서 본다.

## 도메인 규칙

프로젝트 `CLAUDE.md`를 따른다. 화면 기획에 영향을 주는 것:

- **이모지 금지.** 코드, 주석, 커밋 메시지, 와이어 카피 전부.
- 카피는 짧고 건조하게. 서술형 친절체 쓰지 않음.

### 이 프로젝트의 용어

와이어에서 아래 표기를 통일한다.

| 쓸 것 | 쓰지 말 것 |
|-------|-----------|
| 프리셋 | 템플릿, 테마 |
| 시작점 | 기본값, 베이스 |
| 미리보기 | 프리뷰 |
| 내려받기 | 다운로드 |
| 검증 | 유효성 검사, 밸리데이션 |
| 지시 | 프롬프트, 명령 |

### 사용 가능 데이터 토큰

| 토큰 | 뜻 |
|------|-----|
| `{토큰}` | 이번 요청에 쓴 API 토큰 수 |
| `{모델}` | 선택한 모델 이름 |
| `{제공자}` | Anthropic / OpenAI / Google |
| `{프리셋}` | 선택한 프리셋 이름 |

### 사용자에게 노출하면 안 되는 것

- API 키 원문. 등록 후에는 뒤 4자리만 표시한다.
- 시스템 프롬프트 본문, 치환자 계약서 원문.
- 모델이 내놓은 패치의 원본 JSON. 사람이 읽는 요약으로 바꿔 보여준다.

## 유지 항목 (주기적 갱신 필요)

코드에 박아 두는 값이라 시간이 지나면 낡는다. 갱신 시점을 놓치면 사용자가 없는 모델을 고르거나 틀린 비용을 본다.

| 항목 | 어디에 | 왜 낡는가 | 갱신 신호 |
|------|--------|-----------|-----------|
| 추천 모델 목록 | 제공자 어댑터 | 제공자가 새 모델을 내고 옛 모델을 내린다 | 제공자 발표. 또는 받아온 목록에 추천 모델이 없을 때 |
| 모델 단가 | 제공자 어댑터 | 가격이 바뀐다 | 제공자 가격 공지 |
| 키 형식 접두사 | 제공자 어댑터 | 새 키 체계가 생긴다 | 형식 오류 문의가 늘 때 |
| 치환자 계약서 | `webapp/harness/contract.js` | 티스토리가 치환자를 더하거나 뺀다 | 공식 문서 변경 |
| 함정 목록 | `webapp/harness/pitfalls.js` | 티스토리가 내부 마크업을 바꾼다 | 실제 업로드에서 새 문제 발견 |
| 관리자 화면 도식 | D1 | 티스토리가 관리자 UI를 바꾼다 | **사용자 제보뿐.** 우리가 통제하지 못하는 남의 화면이다 |

관리자 화면 도식은 갱신 신호가 약하다. 그래서 D1은 도식을 위치 관계만 남겨 단순하게 그리고, 메뉴 경로 문자열을 항상 병기하며, 기준 날짜를 표시한다. 도식이 틀려도 경로로 찾아갈 수 있게 하는 것이 목적이다.

**추천 모델이 받아온 목록에 없으면 자동으로 감춘다.** 그러면 낡은 추천이 사용자에게 보이는 최악은 피한다. 다만 추천이 하나도 안 남을 수 있으므로 그때는 받아온 목록 전체를 보여준다.

## 규칙

- 흑백만. 그림자, 그라데이션, 컬러 금지. 구조는 1px 보더로 표현한다.
- 모바일 기준으로 먼저 성립하고 768px, 1024px에서 확장한다.
- 새 화면은 4안을 먼저 만들어 선택을 받는다. `{ID}-options.html`
- 화면 HTML은 코드로 취급해 직접 편집한다.
