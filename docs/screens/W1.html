의도

대화 기록이 곧 작업 기록이 되게 했다. 무엇을 어떻게 바꿔 왔는지가 왼쪽에 그대로 남아, 마음에 안 들 때 어느 지점으로 돌아갈지 고르기 쉽다.

응답에 바뀐 항목을 목록으로 붙인다. 모델이 무엇을 건드렸는지 사용자가 미리보기만 보고 짐작하지 않게 한다.

검증 실패는 자동으로 다시 시키지 않는다. API 비용이 사용자 지갑에서 나가므로 몇 번 더 돌릴지는 사용자가 정해야 한다. 대신 무엇이 왜 막혔는지 그대로 보여준다.

실패해도 직전 결과를 지우지 않는다. 되돌아갈 자리가 항상 있어야 마음 놓고 시킬 수 있다.

토큰 사용량을 하단에 상시 노출한다. 남의 지갑이 아니라 자기 지갑이므로 감출 이유가 없다.

대안

  • 보편 B 미리보기 전면 - 판단은 정확하지만 대화 기록이 접혀 문맥을 놓친다. 큰 화면이 필요한 순간은 상태 4 확대로 해결했다.
  • 실험 A 직접 지목 - 지시가 짧아지고 토큰도 덜 들지만, 미리보기 요소와 코드를 잇는 대응표를 프리셋마다 유지해야 한다. 프리셋을 늘릴 때 비용이 같이 늘어 보류.
  • 실험 B 시도 타임라인 - 되돌리기가 일급이 되는 점이 좋았다. 대화 안의 "이 지점으로 되돌리기"로 축소해 흡수했다.

미정

  • 결정됨 - 코드 패널은 읽기 전용. 편집을 허용하면 사용자 편집분과 모델 패치를 병합해야 하는데, 그것은 작은 기능이 아니라 별도 문제다. 지금 떠안지 않는다.
  • 결정됨 - 모델에는 현재 스킨 상태와 최근 대화 몇 턴만 보낸다. 전량 전송은 대화가 길어질수록 비용이 선형으로 늘고, 오래된 지시가 현재 결과와 어긋나 오히려 방해가 된다. 범위를 사용자에게 노출하지 않는다. 설명이 어렵고 잘못 고르면 결과만 나빠진다.
  • 미리보기 페이지 타입 7종을 한 번에 다 보여줄지, 지금처럼 하나씩 전환할지.
  • 결정됨 - 세부 패널을 두지 않는다. P2 에서 정한 값을 여기서 또 패널로 고칠 수 있게 하면 경로가 둘이 되어 어느 쪽이 최신인지 헷갈린다. 여기서는 대화로만 바꾼다.
  • "그냥 두기"를 골랐을 때 그 실패를 대화 기록에 남길지 지울지.
